# proto

The one wire schema. Everything that crosses a process boundary is defined here and generated
for Rust (`wire/`, via `prost-build` with `protox`, no system protoc; `controller/` and `store/`
use the wire crate's types) and Python (`core/everserve/proto/`, generated by
`scripts/gen-proto.sh` and committed; the gate fails if the generated code is stale).

- `signals.proto`: the signal protocol between the controller and an engine's processes: notice,
  rank lost, rank joining, membership committed, the join payload, the cover plan; the only
  messages the controller sends into an engine process and an adapter sends out.
- `mirror.proto`: the committed-KV service: committed rows in with their epoch, restore out, the
  last committed token per request, replication between stores and the compile cache's files.
- `policy.proto`: the deployment's policy document.
- `discovery.proto`: a node daemon's record: where it listens, which engines it serves.
- `coord.proto`: the protocol between a node daemon and the coordinator (decision 0014): hello,
  reports, changes delivered and acknowledged, every message carrying the epoch.
- `spec.proto`: desired state (decision 0036): what each resource should be, written only through
  the operator API and kept in the spec store, and the status the coordinator alone keeps across
  a restart.

`core/everserve/contract/signals.py` keeps plain dataclasses with the same fields for in-process
use; a test round-trips them through the generated messages so the two cannot drift.
