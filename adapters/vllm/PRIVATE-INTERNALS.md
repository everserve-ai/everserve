# Private vLLM internals the adapter depends on

vLLM pin: `db9527a46873454610df6dbedf79a36d6bf1a7f6`, the v0.31.0 release (`adapters/vllm/PIN`,
PyPI `vllm==0.31.0`). **No file under `vllm/` is edited.**

A line counts if it imports, subclasses, calls or patches a vLLM name that is not a documented
plugin, connector, executor or model-registration surface (`CONTRIBUTING.md`, rule 1). Each row
anchors the adapter side as `file.py:function` or `file.py:Class.method` under
`adapters/vllm/everserve_vllm/`, and the pin side as `vllm/path/file.py:Symbol:line`, the line
read in vLLM's source at this pin. "Why" is the rule, in the present tense; the run that found it
is in `docs/decisions/` and `bench/runs/`. "Upstream hook" is what vLLM would offer to retire the
row; "none" where the reach is a plain import of a stable name.

Every row is kept current at every pin move. `tests/test_private_internals_ledger.py` parses this
file and the adapter's source and fails when an adapter anchor no longer names a function or
method that exists, when the adapter imports a vLLM module no pin anchor names, when a private
attribute reach the test greps for has no row, or when a function that assigns onto a vLLM or
torch object is not in the Patches section.

Rows A1 to A49 keep the numbers the decisions and docstrings cite (A7 was never assigned); A50 on
were added when the ledger was regenerated against this pin. Patches are listed again, with their
scope, under [Patches](#patches).

## Patches

Everything that assigns onto a vLLM or torch object, in one place. "Process-wide" is a module
global or class attribute; "instance" an attribute of one object; "temporary" is restored or
deleted before the installing function returns. The test requires every function that assigns
onto such an object to be anchored here, by itself or by its class.

Every process-wide permanent patch is installed by the registry, `patches.py`, one class per
patch (`StepFn`, `ExecutorClass`, `AllReduce`, `Pipeline`, `LogprobWarmup`), in that order:
`patches.install()` puts each on under its condition (A47 and A48 in every process, the rest
where the launcher set `EVERSERVE_GRAPH_SAFE`), `patches.uninstall()` puts each original back,
`patches.installed()` lists what is on. The instance and temporary patches below are the owning
module's, named in the registry's docstring; `tests/test_patches.py` holds the two lists to this
section.
